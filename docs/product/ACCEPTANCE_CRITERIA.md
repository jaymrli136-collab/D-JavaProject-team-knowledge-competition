# 验收标准

## 1. 核心验收链路

### AC-01 多项目知识检索

- 用户选择两个有权访问的项目。
- 提问：“比较两个项目当前最大的风险。”
- 系统分别召回两个项目证据。
- 回答按项目组织，并为每个项目提供引用。

### AC-02 项目隔离

- 使用 `u_alice` 查询“头条热点专题的风险”。
- `u_alice` 不是该项目成员。
- 系统不得返回该项目的标题、摘要、片段或决策。
- API 返回明确的 `FORBIDDEN`。

### AC-03 引用可追溯

- 每条引用包含 evidenceId、项目、文档、章节、来源、版本和有效期。
- 回答中的 `[E1]` 必须能在 evidence 列表中找到。
- 不存在的引用 ID 必须被校验器移除。

### AC-04 无证据拒答

- 提问知识库中不存在的信息。
- 系统状态为 `ABSTAINED`。
- 回答不得编造具体事实。
- 系统给出补充材料建议。

### AC-05 会话追问

- 第一轮锁定“红果短剧内容推荐”。
- 第二轮提问“那它最大的风险是什么？”
- 系统沿用上一轮项目范围。

### AC-06 知识录入

- 在已有项目中录入一份新文档。
- 文档被切分为至少一个章节。
- 新文档可以立即被检索。
- 文档带有版本、有效期和来源。

### AC-07 固定评测

- 调用评测接口后返回每个用例的状态。
- 汇总通过率、引用覆盖率、拒答正确率和权限隔离结果。
- 失败用例包含问题、预期和实际状态。

## 2. 演示脚本

1. 以 `u_alice` 登录，查看可见项目。
2. 询问番茄小说项目的实验结论，展示回答和引用。
3. 追问“那它当前最大的风险是什么”，展示会话继承。
4. 选择两个项目，询问风险对比，展示跨项目证据。
5. 询问知识库中不存在的“下一季度预算”，展示拒答。
6. 切换到 `u_bob`，展示可见项目变化。
7. 运行评测面板，展示通过率和权限隔离结果。

## 3. Definition of Done

- `mvn test` 通过。
- 应用在 8088 端口启动。
- 首页能够提问、查看引用和运行评测。
- README 与实际启动方式一致。
- 成果提交并推送至指定公开仓库。
