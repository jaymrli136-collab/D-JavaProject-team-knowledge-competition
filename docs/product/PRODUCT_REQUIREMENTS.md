# 产品需求文档

## 1. 产品定位

**产品名称**：Project Atlas  
**赛题**：为知识密集型、多项目并行团队构建知识问答 Agent Harness  
**目标**：让团队成员跨项目检索分散知识，定位历史决策和负责人，并在每个结论后查看可追溯的原文证据。

Project Atlas 不是通用聊天机器人，而是面向多项目协作的可信知识工作台。系统必须同时解决：

1. 文档分散、命名不统一、项目边界模糊。
2. 回答看似合理但无法核实来源。
3. 成员权限不同，检索时容易越权。
4. 文档存在新旧版本冲突，模型无法判断时效性。
5. Agent 多轮执行过程不可观测、不可恢复、不可评测。

## 2. 目标用户

### 项目负责人

关注项目状态、关键决策、风险和待办，需要快速完成项目交接和跨项目比较。

### 运营成员

需要查找活动规则、指标口径、历史实验和相关文档，避免重复提问和重复试错。

### 新加入成员

需要快速理解项目背景、术语、负责人和关键约束，并知道答案来自哪里。

## 3. 核心用户故事

- 作为项目成员，我可以用自然语言询问项目状态，并查看答案背后的文档和日期。
- 作为项目负责人，我可以比较两个项目的目标、风险和关键决策。
- 作为运营成员，我可以查询历史决策及依据，并直接查看原文。
- 作为新成员，我可以连续追问，系统能够沿用上一轮项目范围。
- 作为非项目成员，我无法通过提问、检索或引用看到未授权项目的信息。
- 作为知识维护者，我可以录入文档并立即被检索，同时保留版本、有效期和来源。
- 作为比赛评委，我可以运行固定评测集，查看引用、拒答和权限隔离结果。

## 4. 功能范围

### P0：当前版本必须完成

- 项目、文档、章节、决策和成员权限建模。
- Markdown/纯文本知识录入，按标题层级切分内容。
- 项目级 ACL，召回结果在进入 Agent 上下文前完成权限过滤。
- L0 文档摘要、L1 文档概览、L2 章节原文。
- BM25 + 哈希向量混合召回和轻量 Rerank。
- 显式 Agent Harness：作用域识别、查询计划、检索、回答、引用校验和轨迹记录。
- 引用包含项目、文档、章节、版本、来源、有效期和证据 ID。
- 证据不足时拒答。
- Session 级上下文，支持连续追问沿用项目和问题范围。
- 项目记忆治理：候选项绑定 AgentRun 与 evidenceId，经成员确认后生效，支持撤回审计。
- 内置多项目演示数据和固定评测任务。

### P1：后续增强

- PDF/Word/Excel 解析和对象存储。
- PostgreSQL、pgvector 与全文索引持久化。
- 记忆版本对比和自动过期策略。
- 飞书文档与机器人接入。
- SSE 流式进度、取消和断点恢复。
- 原文定位和高亮。

### P2：产品化增强

- 自动事实抽取与冲突检测。
- Sub-agent 并行研究。
- 知识图谱和调用链影响分析。
- 记忆质量评分、TTL 和淘汰机制。
- 多租户和生产级可观测性。

## 5. 非功能要求

- **可信**：关键事实必须有证据，不能把模型猜测包装成确定结论。
- **隔离**：服务端从身份计算 ACL，不能信任 LLM 或前端传入的范围。
- **可解释**：返回查询计划、证据、引用校验和耗时轨迹。
- **可评测**：固定任务能够重复运行并回归验证。
- **可运行**：默认无需外部模型或数据库。
- **可扩展**：检索、LLM、存储和记忆模块通过接口隔离。

## 6. 赛题映射

| 赛题要求 | 产品响应 |
|---|---|
| 知识密集型 | 分层摘要、混合检索、章节级证据 |
| 多项目并行 | 项目命名空间、跨项目查询、成员 ACL |
| Agent Harness | 显式状态机、RunState、工具路由和轨迹 |
| 随时可问 | 对话入口与会话上下文 |
| 可信可溯源 | 原文引用、版本、有效期和引用校验 |
| 可落地 | 可运行 MVP、固定评测和可观测指标 |

## 7. 成功指标

- 固定评测集通过率 >= 85%。
- 可回答问题引用覆盖率 >= 90%。
- 无答案问题拒答正确率 >= 80%。
- 未授权项目泄漏次数 = 0。
- Mock 模式 P95 响应时间目标 < 2 秒。

## 8. 关键边界

- 系统不会自动把模型生成内容写入权威知识库。
- 会话记忆不代表项目事实，项目事实必须来自可追溯文档。
- 前端隐藏不是权限控制，权限必须在服务端检索前执行。
- P0 使用内存存储，生产版本替换为 PostgreSQL。
